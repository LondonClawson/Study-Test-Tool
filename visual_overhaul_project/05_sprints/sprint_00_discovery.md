# Sprint 0: Discovery And Context

## Sprint Goal

Create enough reusable context that implementation agents can work from focused
stories instead of repeatedly exploring the full GUI.

Sprint 0 is a research sprint. Its primary output is assignment-grade context,
not visual implementation.

## Candidate Stories

- `04_stories/STORY-001_context_batch_one.md` as a PM tracking wrapper.
- `04_stories/STORY-002_baseline_visual_audit.md` as an audit coordination
  wrapper.

## Candidate Research Tasks

- `02_research_tasks/R-002_component_style_inventory.md`.
- `02_research_tasks/R-001_baseline_visual_audit.md`.
- Run screen-specific research tasks early only if Sprint 1 implementation needs
  them immediately.

Assign `R-001` and `R-002` as separate Dev 1 research tasks where practical.
They produce the required inputs for the visual foundation story.
Do not assign blocked screen-specific research early unless the PM records the
reason in the assignment packet.

Ready-to-use packets live in
`06_handoffs/sprint_00_assignment_packets.md`.

## Exit Criteria

- `style_inventory.md` exists.
- `baseline_visual_audit.md` exists or blocked states are documented.
- Screenshot baseline folder exists or screenshot blockers are documented.
- Context index statuses are updated.
- Sprint 1 stories have clear required context.
- Completed summaries pass `00_project/definition_of_ready.md`.

## Review Questions

- Did the audit reveal any MVP scope changes?
- Which issues are app-wide foundation issues vs screen-specific issues?
- Are there enough realistic screenshots to compare against later?
- Are any CustomTkinter constraints likely to block the visual direction?
- Can Dev 2 start `STORY-003` without repeating broad GUI exploration?
