# Sprint 2: Core Study Flow

## Sprint Goal

Polish the screens users see during and immediately after studying: test-taking,
answer interaction, practice feedback, and results.

## Candidate Stories

- `04_stories/STORY-010_test_taking_shell.md`.
- `04_stories/STORY-011_answer_rows_and_practice_feedback.md`.
- `04_stories/STORY-012_results_summary_and_review_cards.md`.

## Required Context Before Planning

- `01_context/summaries/test_taking_context.md`.
- `01_context/summaries/results_context.md`.
- `01_context/summaries/visual_foundation_decisions.md`.
- Handoff notes from Sprint 1 foundation stories.

## Exit Criteria

- Test-taking shell is focused and readable.
- Answer rows and practice feedback are polished without changing scoring or
  practice lock behavior.
- Results summary and review cards are easier to scan.
- Relevant tests are run for any behavior-bearing changes.
- Light/dark and minimum-size notes are recorded for core flow screens.

## Review Questions

- Is question text still dominant?
- Are answer states and practice feedback clear?
- Is Finish styled as a normal workflow completion instead of an alarming
  destructive action, if approved by the foundation?
- Are results understandable at a glance?
