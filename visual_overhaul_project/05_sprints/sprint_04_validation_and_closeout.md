# Sprint 4: Validation And Closeout

## Sprint Goal

Validate the MVP visual overhaul across screens, modes, and minimum size, then
close the MVP with evidence and a clean post-MVP backlog.

## Candidate Stories

- `04_stories/STORY-016_light_dark_and_min_size_validation.md`.
- `04_stories/STORY-017_mvp_visual_regression_pass.md`.

## Required Context Before Planning

- `03_backlog/acceptance_matrix.md`.
- `01_context/summaries/baseline_visual_audit.md`.
- `01_context/summaries/visual_foundation_decisions.md`.
- All completed story handoffs.

## Exit Criteria

- Every MVP screen is checked in light and dark mode.
- Every MVP screen is checked at the minimum supported window size.
- Before/after comparison is documented.
- Tests are run or skipped with reasons.
- Remaining issues are classified as blockers, post-MVP follow-ups, or accepted
  limitations.
- Product owner can accept or reject the MVP using documented evidence.

## Review Questions

- Does the app meet every MVP acceptance matrix row?
- Are any changes behaviorally risky?
- Which post-MVP items are worth pursuing first: icons, dialogs, responsive pass,
  chart styling, navigation, or branding?
