# Context Summary Template

## Metadata

- Summary ID:
- Summary file:
- Created:
- Last updated:
- Produced by research task:
- Research agent:
- Source files inspected:
- Screens/states inspected:
- Screens/states not inspected:

## Purpose

State what future agents should learn from this summary and which story types
should read it.

## Current Structure

Describe the relevant modules, classes, widgets, screen lifecycle methods, and
dependencies.

## Important UI States

List the states an implementation agent must preserve or verify.

## Workflow Map

List the relevant user actions, navigation paths, callbacks, and state changes
that visual work must preserve.

## Visual Findings

Describe observed spacing, hierarchy, colors, typography, cards, rows, empty
states, loading states, dialogs, and light/dark issues. Keep observed facts
separate from recommendations.

## Recommendations For Implementation Stories

List recommended visual changes, likely files, and any story splits needed before
junior implementation assignment.

## Behavior Constraints

List workflows and behavior that must not change during visual work.

## Implementation Risks

List likely regression risks, fragile widget interactions, or state coupling.

## Open Questions

List product/design questions that need a decision before implementation.

## Dev 2 Quick Start

Write five to ten bullets that tell the implementation agent exactly where to
start, which files or methods matter most, which states to check, and what risks
to avoid. This section should prevent broad rediscovery.

## Refresh Triggers

List file changes, design decisions, or completed stories that require this
summary to be updated.
